# Демо: выдуманная система «Demo Library»

Здесь всё выдумано: система, репозитории, пакеты (`org.example`), компоненты, номера находок и идентификаторы
уязвимостей. С реальными выгрузками и проектами демо не связано. Оно нужно, чтобы попробовать приложение без
настоящих данных.

## Что внутри

- `repos/billing-core` – сервис счетов на Java (Maven).
- `repos/catalog-api` – каталог товаров на Python.
- `demo-hub-report.xlsx` – синтетическая выгрузка в формате отчёта AppSec.Hub. Её строит сценарий
  `scripts/make_demo_xlsx.py` (см. ниже); готовый файл лежит в репозитории, чтобы всё воспроизводилось сразу.
- `demo-hub-report-v2.xlsx` – вторая выгрузка той же системы для проверки повторного импорта: без находки
  100115, с новой находкой 100116, у 100105 другая строка кода (`make_demo_xlsx.py --variant v2`).
- `sca-answers.json` – пример ответа внешнего агента по библиотекам SCA в формате из задания: три ответа –
  «обновить», «не применимо» и «неясно». Ссылки в нём ведут на выдуманные адреса в зоне `.example`: в карточке
  они помечены «не первоисточник» и в текст для Hub не попадают.

В коде репозиториев **нарочно** оставлены уязвимые места (внедрение SQL-кода, обход пути, межсайтовый скриптинг,
внедрение команд ОС, небезопасная десериализация, слабые генератор случайных чисел и хеш, пароль в исходном коде)
и рядом с ними безопасные варианты похожего кода, на которые анализатор тоже мог бы сработать. Этот код только
читается приложением и никогда не запускается. Не используйте его как образец и не собирайте.

Что демонстрирует выгрузка:

- 15 находок SAST, 4 находки SCA Security, 1 находка SCA Compliance и 1 находка DAST, сводка «Summary Report»
  сходится с листами;
- кодовая база `Catalog_API` в выгрузке называется не так, как папка `catalog-api`: соответствие подбирается
  автоматически (без учёта регистра и разделителей);
- кодовой базы `notify-gateway` среди папок нет: по её находке контекстом служит только строка кода из выгрузки;
- у одной находки строка кода в выгрузке не совпадает со строкой в репозитории: так выглядит репозиторий не на
  коммите скана;
- у одной находки путь файла начинается с имени кодовой базы: файл всё равно находится;
- у находки о пароле в исходном коде значение пароля перед отправкой модели заменяется плейсхолдером;
- у SCA в колонке «CVE id» встречаются идентификаторы AppSec.Track (`AST-…`) и GHSA, а в колонке CWE – список
  («1333, 400»); у всех SCA-находок уровень политики Hub «Critical», а срочность считается по CVSS.

## Какой ответ задуман

По этой таблице удобно оценить модель: сколько безопасных мест она признаёт ложными срабатываниями и не
подтверждает ли всё подряд. Из 15 находок SAST задумано 9 истинных, 5 ложных и 1 неясная.

| Находка | Где | Задуманный ответ | Почему |
|---|---|---|---|
| 100101 | `InvoiceRepository.findByCustomer` | истинная | `customerId` склеивается в текст SQL-запроса без параметров |
| 100102 | `InvoiceRepository.findByStatus` | ложная (допустимо «неясно») | в запрос попадает `status.name()` перечисления `InvoiceStatus` – только имена его констант; само перечисление – в другом файле, поэтому «неясно» с просьбой посмотреть `InvoiceStatus` – тоже честный ответ |
| 100103 | `InvoiceExportController.downloadInvoice` | истинная | имя файла из запроса без нормализации и проверки: `../` выводит за папку выгрузок |
| 100104 | `InvoiceExportController.downloadReport` | ложная | путь нормализуется и проверяется `startsWith(EXPORT_DIR)` до чтения файла |
| 100105 | `InvoiceExportController.showGreeting` | истинная | параметр `name` выводится в HTML без экранирования; строка в выгрузке отличается от клона – карточка предупреждает |
| 100106 | `PaymentTokenService.newPaymentToken` | истинная | токен оплаты строится на `java.util.Random` – предсказуемый генератор |
| 100107 | `PaymentTokenService.shuffleBannerOrder` | ложная | случайный порядок баннеров ничего не защищает: криптостойкий генератор не нужен |
| 100108 | `PaymentTokenService.cardFingerprint` | истинная | MD5 от номера карты: короткий номер перебирается, отпечаток раскрывает карту |
| 100109 | `DatabaseSettings` | истинная | пароль к базе записан в исходном коде (модель видит его скрытым) |
| 100110 | `products.search_products` | истинная | строка поиска подставляется в SQL через f-строку |
| 100111 | `products.get_product` | ложная | параметризованный запрос: значение передаётся отдельно от текста SQL |
| 100112 | `tasks.unpack_supplier_archive` | истинная | имя файла подставляется в команду, которая выполняется через оболочку (`shell=True`) |
| 100113 | `tasks.load_import_settings` | ложная | `yaml.safe_load` не создаёт произвольных объектов |
| 100114 | `tasks.restore_cart` | истинная | `pickle.loads` значения из cookie – выполнение кода при десериализации |
| 100115 | `notify-gateway` (клона нет) | неясно | видна одна строка: параметр запроса становится адресом, а запрос по нему – вне видимости; нужен клон |

## Как попробовать

Кнопка «Создать демо-проект» на странице проектов загружает `demo-hub-report.xlsx` и выбирает папку `repos`.
Пошагово – [docs/DEMO.md](../../docs/DEMO.md).

Если выгрузки нет (например, после правки демо-кода её нужно перестроить), построить её можно двумя способами.

1. В образе приложения – ничего не ставится на компьютер, работает и в закрытом контуре. Образ должен уже быть
   (после `.\start.ps1` или `scripts\import-image.ps1`). Из корня репозитория в PowerShell:

   ```powershell
   docker run --rm --network none -v "${PWD}:/work" -w /work local-triage:latest python scripts/make_demo_xlsx.py
   ```

2. В окружении разработки (нужен Python 3.11 или новее):

   ```powershell
   python -m venv .venv
   .venv\Scripts\python -m pip install -r requirements.txt
   .venv\Scripts\python scripts\make_demo_xlsx.py
   ```

Файл появится в `examples/demo/demo-hub-report.xlsx`; другой путь можно задать параметром `--out`. Перестроенную
выгрузку загрузите в демо-проект («Загрузить другую выгрузку») – решения по совпадающим находкам сохранятся. Если
корень папок с репозиториями не включает папку приложения, кнопка «Создать демо-проект» берёт копию выгрузки
из образа – тогда пересоберите его: `.\start.ps1 -Build`.
