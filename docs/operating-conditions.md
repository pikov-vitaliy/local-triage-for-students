# Условия эксплуатации: что действует, что снято

Перечень условий, при которых приложение рассчитано на работу одного оператора, и долга, который эти условия
порождал. Первый перечень составлен при приёмке 0.9.5 (21.10.2026) по четырём разборам (архитектура, сценарий
оператора, приватность, независимое ревью); здесь – его состояние на 0.9.13.dev3 (25.10.2026). Снятые условия
остаются в таблице с версией, где они сняты, чтобы не искать по CHANGELOG.

## Условия, которые действуют

| № | Условие | Почему | С какой версии |
|---|---|---|---|
| У1 | Одна папка данных – один экземпляр приложения. Второй экземпляр на той же папке не запустится (замок `data/telemetry/instance.lock`; основную базу охраняет замок экземпляра в PostgreSQL); замок руками не удалять | одновременная запись двух экземпляров в одну базу недопустима | 0.3.x; с 0.9.10 удалённый замок держатель восстанавливает сам, а при устаревшей своей отметке прекращает записи |
| У2 | Видеопамять: локальная модель должна помещаться на видеокарту; перед прогоном закрыть программы, занимающие видеопамять (ВМ, браузеры с ускорением). «Модель не помещается – часть слоёв на процессоре» видно на странице прогона | скорость разбора падает в разы | 0.5.0 (наблюдение GPU/VRAM) |
| У3 | Новое сканирование после удаления или смены клонов – новым проектом: срез кода в базе доказывает, что видел оператор, а не что код актуален | решение привязано к отпечатку кода | 0.8.x (срезы в базе) |
| У4 | Перед большими объёмами – проверенная копия базы `.\scripts\backup-db.ps1 -Check` (база в томе `pgdata`, копия папки `data/` её не содержит); перед обновлением схемы копию в `backups/` снимает и проверяет `.\start.ps1 -Migrate` (ADR-0128), старые копии удаляет `backup-db.ps1 -Keep <N>`, по умолчанию копии не удаляются | откат при сбое | 0.9.8 (копия перед схемой), 0.9.13 (список и удаление в настройках); 0.10.0.dev4 – копии сценариями, списка в «Настройках» нет |
| У5 | Журнал обмена с моделью (`data/model-traffic`) растёт без предела и содержит маскированный код: срок хранения и удаление – за владельцем, автоматической очистки и кнопки «Очистить» нет и не будет ([model-traffic-log.md](model-traffic-log.md); удаление только вручную) | ADR-0074 | 0.5.x |
| У6 | Приёмка текстов в корпоративном Hub – за оператором: первые карточки переносятся вручную и сверяются; приложение текст выдаёт только по решению человека (ADR-0088) | модель – подсказка | 0.9.5 |
| У8 | Внешние провайдеры моделей: ключ хранится в приложении, профиль проекта выбирает оператор; код проекта уходит внешней модели только у проекта с отметкой «код не секретный» после предпросмотра промпта; исследование компонентов провайдером – после предпросмотра задания и согласия ([external-providers.md](external-providers.md), ADR-0104, ADR-0105). Обращение без ответа – «результат неизвестен», повтор платного запроса – только по кнопке | данные наружу – по решению владельца | 0.9.13 |
| У9 | В ВМ работает тот же экземпляр, что на компьютере (один источник правды); база в ВМ отдельно не ведётся | две базы не сливаются | 0.9.12 |
| У10 | Вердикт модели, ответ внешнего агента и исследование компонентов – подсказки: решение, текст для Hub, целевая версия и применимость уязвимостей – за оператором с обоснованием (ADR-0088, ADR-0091, ADR-0094, ADR-0101) | ответственность за текст в Hub | 0.9.5–0.9.11 |

## Условия, которые сняты

| Было (21.10, 0.9.5) | Снято | Как |
|---|---|---|
| Менять номер дефекта и копировать текст только из одной актуальной вкладки | 0.9.8 | выдача из вкладки, открытой до смены номера, номер не перезаписывает; занятый номер – только после подтверждения; номер другого набора – отказ |
| Во время прогона не загружать большие выгрузки и ответы агентов (`DatabaseBusy` переводил прогон в «ошибка») | 0.9.10 | занятая база: запись повторяется, затем прогон встаёт на паузу с причиной, находка остаётся в очереди; «Продолжить» разбирает её заново |
| Замок `instance.lock` при зависании – только перезапуск контейнера | 0.9.10 | держатель восстанавливает удалённый замок сам; устаревшая своя отметка – записи прекращаются с понятной причиной |
| Копии баз перед миграциями копятся в `data/` – выносить вручную | 0.9.13 | список копий с датой и размером в «Настройках», удаление выбранных с подтверждением (Э9); с 0.10.0.dev4 списка в «Настройках» нет: копии – в `backups/`, хранение – `backup-db.ps1 -Keep <N>` |
| Порт только на `127.0.0.1`: из ВМ – только через SSH-туннель | 0.9.12 | доступ из локальной сети по выбору владельца (ADR-0103); условие У7 |

## Долг из приёмки 0.9.5 – состояние

| Долг | Состояние |
|---|---|
| Ретенция журнала обмена с моделью | закрыт: удаление только вручную, в приложении не меняется (У5) |
| Пауза вместо «ошибки» при `DatabaseBusy` / `LockUnsure` | закрыт в 0.9.10 |
| Самовосстановление удалённого замка | закрыт в 0.9.10 |
| Автоматическая копия базы перед сменой схемы | закрыт в 0.9.8 (ADR-0093), список в настройках – 0.9.13 (снят в 0.10.0.dev4; с 0.10.0 – проверенная копия при `start.ps1 -Migrate`, ADR-0128) |
| История текста комментария SAST | закрыт в 0.9.9 (`review_texts`, блок «Прежние редакции текста») |
| `window.confirm` при клавише `c` сам ставил «Текст проверен» | закрыт в 0.9.9: подсказка и фокус на флажок, окно браузера не открывается |
| Короткие тексты SCA с «(окончательная редакция)» по ГОСТ Р КАПО | закрыт в 0.9.8: короткий текст SCA – только обоснование оператора, с 0.9.11 – с публичным номером и компонентом |
| Дубли номеров дефектов не блокировались | закрыт в 0.9.8: занятый номер – только после подтверждения, номер другого набора – отказ |

## Как пользоваться перечнем

Перед вопросом «можно ли …» в работе – сверяться с таблицей действующих условий. Снимая условие кодом, переносить
строку во вторую таблицу с версией. Приёмка нового выпуска – повод перечитать обе таблицы.
