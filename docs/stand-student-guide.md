# Учебный стенд «Локальный триаж»: руководство студента

Стенд – приложение для разбора результатов анализа защищённости кода. На нём вы учитесь тому, что делает
специалист по безопасной разработке после запуска анализаторов: отличать настоящую уязвимость от ложного
срабатывания, оценивать уязвимости сторонних компонентов и их лицензии, оформлять дефект для команды разработки.
Находки берутся из десяти открытых уязвимых приложений и выдуманной Demo Library, у каждого – готовая выгрузка в
формате AppSec.Hub.

## 1. Установка и первый запуск

Нужен Node.js 20 или новее, Docker не нужен. На Windows Node.js ставится одной командой в PowerShell, на сайт
заходить не нужно:

```
winget install OpenJS.NodeJS.LTS
```

Если Windows спросит разрешение на изменения, ответьте «Да». После установки закройте окно терминала и откройте новое,
иначе команды `node` и `npm` не найдутся. Проверка: `node -v` – должно быть v20 или больше. Старый Node.js обновляется
так же: `winget upgrade OpenJS.NodeJS.LTS`. Если winget отключён, скачайте установщик LTS с https://nodejs.org.

Затем в терминале:

```
npx local-triage
```

Первый запуск занимает несколько минут: ставятся Python и зависимости приложения, создаётся база PostgreSQL. Затем
открывается браузер со страницей стенда. Окно терминала не закрывайте, пока работаете: оно держит приложение. Чтобы
остановить стенд, нажмите Ctrl+C в этом окне.

Где что лежит, показывает `npx local-triage --where`: служебная папка (база, журналы) и папка кода, куда скачиваются
примеры. Проверка установки – `npx local-triage --doctor`.

## 2. Модель

Модель предлагает вердикт по каждой находке SAST. Решение принимаете вы, вердикт модели – только подсказка.

- **Ollama на своём компьютере.** Подходит при видеокарте с памятью от 16 ГБ. Установите Ollama (https://ollama.com), выполните
  `ollama pull gpt-oss:20b`, откройте «Примеры», затем «Начало работы», выберите заготовку «Ollama на этом компьютере» и нажмите
  «Проверить».
- **DeepSeek.** Подходит, если мощной видеокарты нет. Нужен свой ключ API. Заготовка DeepSeek заполняет адрес и модель; вставьте ключ,
  нажмите «Проверить» и «Сохранить». Поставьте лимит расхода ключа в кабинете провайдера. Данные обрабатываются
  провайдером в КНР (https://cdn.deepseek.com/policies/en-US/deepseek-privacy-policy.html), цены –
  https://api-docs.deepseek.com/quick_start/pricing.

Заготовка DeepSeek заполняет и раздел «Дополнительно»: рассуждение, пределы ответа и поиск – рекомендуемыми значениями,
у каждого поля есть подсказка. У профиля, созданного раньше, нажмите «Подставить рекомендуемые значения DeepSeek».

Код уходит внешнему провайдеру только у проекта с отметкой «код не секретный». Проекты учебных примеров получают её
сразу: у десяти скачиваемых примеров открытый код, у Demo Library – выдуманный, написанный для стенда. У своего проекта
отметку ставите вы сами в параметрах проекта, после предпросмотра того, что получит модель; без неё разбор через
DeepSeek откажет с объяснением. Снять отметку можно там же.

Выбранный профиль сохраните как «Профиль для примеров»: он назначается каждому новому проекту из десяти учебных
приложений каталога. Demo Library получает профиль по умолчанию – его можно сменить в параметрах проекта.

## 4. Разбор находок SAST

SAST (статический анализ) ищет в исходном коде опасные конструкции по правилам. Правило не понимает программу
целиком, поэтому часть срабатываний ложная: данные на самом деле проверяются, функция не вызывается из внешнего
запроса, строка – пример в тесте.

Порядок работы с находкой:

1. Прочитайте правило и класс CWE в карточке. Ссылка CWE ведёт на описание класса уязвимости.
2. Посмотрите код вокруг строки срабатывания. «Открыть в VS Code» открывает файл на нужной строке.
3. Проследите, откуда приходят данные (источник) и куда попадают (приёмник). Уязвимость обычно там, где данные извне доходят
   до опасной операции без проверки или экранирования.
4. Сравните свой вывод с вердиктом модели. Расходится – разберитесь, кто ошибся и почему.
5. Решение:
   - «Ложное срабатывание» – с коротким комментарием, почему;
   - «Подтверждаю дефект» – находка подтверждена; после сохранения решения появится текст дефекта (раздел 8);
   - «Отложить» – если данных для решения не хватает.

## 5. Уязвимости компонентов (SCA)

SCA (композиционный анализ) сверяет версии сторонних компонентов с базами известных уязвимостей. Выгрузка примеров
собрана OSV-Scanner по зафиксированным версиям зависимостей.

По каждой находке проверьте, уязвима ли именно эта версия и есть ли исправленная (колонка «Версия исправления (Hub)»), и
используется ли уязвимая функция компонента в коде примера: уязвимость в компоненте не всегда достижима из приложения.
Решение – «Обновить» до исправленной версии, «Риск принят» с обоснованием или «Ложное срабатывание».

При исследовании компонента провайдер (DeepSeek с поиском) собирает сведения из открытых источников; выводы проверяйте
по ссылкам.

## 6. Лицензии компонентов

На листе SCA Compliance выгрузки – компоненты, лицензия которых не входит в разрешённый перечень учебной политики:

| Уровень | Лицензии | Что это значит |
|---|---|---|
| High | сильный копилефт: GPL, AGPL и др. | распространение производного ПО – на условиях той же лицензии |
| Medium | слабый копилефт: LGPL, MPL, EPL, OFL и др. | условия касаются изменённых файлов или самой библиотеки |
| Low | прочие вне перечня и «лицензия не установлена» | нужно уточнить условия у правообладателя |

Перечень и классы – учебные. В организации политику лицензий утверждают юристы, и для внутреннего ПО она не такая, как для продукта на
продажу. Находки о лицензиях показаны в общем списке, вид «SCA, лицензии» (ссылка «Находки о лицензиях» на вкладке SCA открывает его сразу).

## 7. Классы уязвимостей в примерах

| Класс | CWE | Как выглядит атака |
|---|---|---|
| SQL-инъекция | CWE-89 | ввод `' OR '1'='1` меняет смысл запроса к базе |
| Межсайтовый скриптинг (XSS) | CWE-79 | скрипт из ввода выполняется в браузере другого пользователя |
| Внедрение команд ОС | CWE-78 | `; rm -rf` после имени файла выполняется оболочкой |
| Внедрение кода | CWE-95 | строка из запроса попадает в `eval` |
| Обход пути | CWE-22 | `../../etc/passwd` вместо имени файла |
| Небезопасная десериализация | CWE-502 | подготовленный объект выполняет код при разборе |
| XXE | CWE-611 | внешняя сущность XML читает файл сервера |
| SSRF | CWE-918 | сервер обращается по адресу, заданному атакующим, в том числе во внутреннюю сеть |
| Секрет в коде | CWE-798 | ключ или пароль виден любому, у кого есть доступ к репозиторию |
| Проверка подписи JWT | CWE-347 | токен без подписи принимается как настоящий |
| Слабая криптография | CWE-327, CWE-328 | пароли под хешем MD5 или SHA-1 подбираются за минуты |

Описания классов – в справочнике CWE на странице «CWE» приложения и на https://cwe.mitre.org.

## 8. Дефект

Дефект – запись для команды разработки: что не так, где, чем грозит и как исправить. На стенде он готовится так:

0. Один раз укажите название команды: «Настройки», раздел «Текст дефекта». Оно стоит в первой фразе дефекта; без
   него текст дефекта не выдаётся, и карточка находки скажет об этом со ссылкой на поле.
1. В карточке находки выберите решение «Подтверждаю дефект», впишите обоснование и рекомендацию по исправлению.
2. Нажмите «Сохранить». Только после сохранения в шаге «Перенос в Hub (ASOC)» появится текст дефекта.
3. Скопируйте заголовок и текст дефекта кнопками «Скопировать заголовок дефекта» и «Скопировать текст дефекта» –
   это и есть результат, который сдаётся. На учебном стенде дефект никуда не отправляется: связи с AppSec.Hub нет.

Хороший дефект:

- указывает файл, строку и фрагмент кода;
- объясняет путь данных от источника до опасной операции, если он есть;
- называет последствия для системы;
- предлагает исправление: параметризованный запрос, экранирование, проверку пути, обновление компонента.

## 9. Так задумано

Это поведение может показаться ошибкой, но оно намеренное.

- **Подробности разбора модели свёрнуты.** Вердикт модели, её уверенность и итог всегда видны вверху карточки. Свёрнут только раздел «Подробности разбора» – что делает код, почему такой вердикт, путь данных. Раскройте его один раз, и стенд запомнит: дальше он будет открыт и в других карточках.
- **«Пересмотреть моделью» и «Убрать в архив» спрятаны в свёрнутых блоках.** Это редкие действия: повторный разбор надолго занимает модель (блок «Пересмотреть моделью» в карточке находки), архив убирает проект из списка (блок «Параметры проекта»). Чтобы их не нажали случайно, они лежат в свёрнутых блоках; архив перед действием спрашивает подтверждение. «Удалить проект» – там же, в «Параметрах проекта», и ведёт на отдельную страницу подтверждения.
- **У примера нельзя создать второй проект.** У каждого примера один проект: в нём хранятся ваши решения. Когда проект создан, на карточке примера стоит «Открыть проект». Чистая копия кода – кнопка «Скачать заново», решения при этом не пропадают.
- **Справочники загружаются по одному.** Пока разбирается один архив, кнопки «Загрузить» в других карточках недоступны. Дождитесь строки «Готово» и загрузите следующий.
- **После снятия стенда через Диспетчер задач следующий запуск ждёт.** Стенд пишет «Прежний процесс приложения ещё держит папку данных – жду…» и меньше чем через минуту продолжает сам, подключаясь к своей базе. Решения не теряются. Обычная остановка – Ctrl+C в окне стенда или закрыть окно.

## 10. Глоссарий

- **SAST** – статический анализ исходного кода без запуска программы.
- **SCA** – композиционный анализ: состав сторонних компонентов, их уязвимости и лицензии.
- **Срабатывание** (находка) – место в коде или компонент, на которые указал анализатор.
- **Ложное срабатывание** – срабатывание без реальной уязвимости.
- **Триаж** – разбор срабатываний: подтвердить, отклонить, отложить.
- **CWE** – перечень классов слабостей ПО (https://cwe.mitre.org).
- **CVE** – идентификатор конкретной известной уязвимости.
- **CVSS** – числовая оценка тяжести уязвимости от 0 до 10.
- **Копилефт** – условие лицензии, по которому производное ПО распространяется на тех же условиях.
- **ASOC** (Application Security Orchestration and Correlation) – класс систем, которые собирают результаты всех
  анализаторов защищённости в одном месте, убирают повторы и ведут решения и дефекты. Пример такой системы –
  AppSec.Hub.
- **Выгрузка Hub** – книга Excel с результатами анализа в формате AppSec.Hub.
