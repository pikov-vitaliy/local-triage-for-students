# Сервер модели в сети: Ollama на другом компьютере (0.9.12)

Как подключить приложение к Ollama, которая работает не на этом компьютере, а на сервере в сети организации:
например, приложение в ВМ VMware и видеокарта физического компьютера, или общий сервер с видеокартой. Решение –
ADR-0102, класс доверия `lan`.

## Что уходит по сети

При разборе кода на сервер в сети уходит то же, что получает Ollama этого компьютера: правило, путь файла и срез кода
находки (после маскирования секретов), вопрос к модели. Код уходит **только на подтверждённые адреса** профиля: если
имя сервера потом разрешится в другой адрес, запрос не отправится, пока адрес не подтвердят заново. Частный адрес сам
по себе не доказывает, что сервер принадлежит организации и ничего не пересылает дальше, – это знает только оператор,
поэтому подтверждение обязательно.

## 1. На сервере с видеокартой

1. Ollama должна слушать сеть, а не только `127.0.0.1`. В Windows – системная переменная окружения
   `OLLAMA_HOST=0.0.0.0` (или адрес нужного сетевого адаптера), затем перезапуск Ollama (значок в области
   уведомлений → Quit, снова запустить). В Linux – `Environment="OLLAMA_HOST=0.0.0.0"` в службе `ollama`.
2. Межсетевой экран пропускает порт `11434` **только с адреса компьютера, где работает приложение** (для ВМ – с её
   адреса). Пример для Windows (PowerShell от администратора, адрес ВМ – свой):

   ```powershell
   New-NetFirewallRule -DisplayName "Ollama для приложения триажа" -Direction Inbound -Protocol TCP `
     -LocalPort 11434 -RemoteAddress 192.0.2.50 -Action Allow
   ```

   Межсетевой экран – системная настройка: приложение и сценарии её не меняют.
3. Проверка с компьютера приложения: `curl http://<адрес сервера>:11434/api/version` отвечает версией Ollama.

Если между приложением и Ollama стоит прокси, который требует ключ (заголовок `Authorization: Bearer`), ключ вводится
в профиле (ниже).

## 2. В приложении: профиль сервера

1. «Настройки» → «Провайдеры моделей» → «Добавить профиль».
2. Название (например, «Видеокарта компьютера»), «Сервер в сети организации», адрес `http://<адрес>:11434` – IP из
   частной сети (10.x, 172.16–31.x, 192.168.x) или имя, которое разрешается только в такие адреса.
3. «Проверить»: приложение показывает адреса, в которые сейчас разрешается имя, **и к серверу пока не обращается**.
   Отметьте адреса, если это ваш сервер, и нажмите «Проверить» ещё раз – появятся версия Ollama и её модели.
4. Модель по умолчанию, окно контекста (больше окно – больше видеопамяти на сервере), рассуждение (модели, которые
   умеют рассуждать, отвечают дольше: у ответа с рассуждением свой предел и свой срок). Предел ответа с рассуждением:
   авто – остаток окна после промпта, не больше 8192 токенов у разбора и 4096 у вопроса; явное число в «Пределах и
   сроках» – ваше, не больше половины окна.
5. Ключ – только если сервер его требует, от 16 знаков (латиница, цифры и `- . _ ~ + / =`): короткий ключ может
   совпасть со словами ответов модели. Ключ хранится в папке данных приложения
   (`data/providers/<номер профиля>.key`), привязан к адресу и подтверждённым адресам; в базу и на страницы он не
   попадает – на странице видно только «задан, …последние 4 знака», в журнале обмена заголовок авторизации
   вырезан. В Windows права файла приложение не
   проверяет: папку данных держите на диске, к которому нет доступа у других пользователей. Ключ входит в резервные
   копии папки данных. Отметка «Сервер требует ключ» включает вход по ключу; сняли – ключ удаляется. После
   «Проверить» поле ключа пустое (страница ключ не показывает): введите его снова перед «Сохранить».

   Граница: приложение само ключ нигде не записывает, кроме своего файла: в журнале обмена заголовок авторизации
   вырезан. Если сервер вернёт ключ в ответе, в журнале обмена он останется – журнал хранит весь обмен байт в байт
   (журнал локальный, его конфиденциальность обеспечивает пользователь;
   [журнал обмена](model-traffic-log.md)). В базу и на страницы такой ключ не попадает: строки ответа очищаются, а
   ответ модели (вердикт, ответ на вопрос), где после всей нормализации ключ оказался буквально, не сохраняется –
   находка или вопрос получают ошибку «Ответ модели содержал ключ профиля». Иные кодировки (base64, `%XX`, сжатие,
   ключ, разнесённый по разным полям) не распознаются: сервер, который нарочно так закодирует ключ, защиту обойдёт,
   но ключ у него и так есть.
6. «Сохранить». Профиль можно сделать профилем по умолчанию для разбора кода или выбрать в параметрах отдельного
   проекта («Профиль модели»). «Пробный ответ» на странице профиля – короткая генерация, чтобы убедиться, что модель
   отвечает.

Сохранение профиля не трогает другие профили: их может быть сколько угодно, переключение – выбором профиля проекта или
профиля по умолчанию.

## 3. Что меняется в работе

- Страница прогона, карточка находки и журнал прогонов называют профиль, которым получен ответ: «Видеокарта
  компьютера (сеть организации)». У ответов, полученных до 0.9.12, – «профиль не записан – разбор до 0.9.12».
- Видеокарта, память и процессор на странице прогона – только у Ollama этого компьютера; у сервера в сети видно
  модели в его памяти (по `/api/ps` сервера).
- Если модель на сервере стала работать медленно, приложение **не выгружает** её само (общий сервер может выполнять
  чужие задачи), а предупреждает; выгрузку можно разрешить в профиле.
- Прогон работает по снимку профиля, сделанному при запуске: адрес сервера – из снимка. Выключили профиль, сняли
  подтверждение адреса, в который разрешается имя, или ключ теперь задан для другого адреса – запрос не уходит, прогон
  встаёт на паузу с причиной; «Продолжить» запускает неразобранные находки новым прогоном на действующем профиле
  проекта. Сменили только адрес или порт в профиле без ключа, а прежний адрес по-прежнему подтверждён – начатый прогон
  продолжает на прежнем адресе; новый адрес действует со следующего прогона, «Повторить ошибочные» его прогона уже
  не переносит (снимок не совпадает с профилем).
- При загрузке ВМ прогревается только модель профиля по умолчанию класса «этот компьютер»; сервер в сети не
  прогревается.

## 4. Если не работает

| Что видно | Что проверить |
|---|---|
| «Отметьте адреса сервера…» | Адреса не подтверждены – отметьте их и нажмите «Проверить» ещё раз |
| «…это не частная сеть» | Адрес или имя ведёт во внешнюю сеть: сервер в сети организации должен иметь частный адрес |
| «Ollama не отвечает … соединение отклонено» или срок истёк | `OLLAMA_HOST` на сервере, перезапуск Ollama, правило межсетевого экрана, адрес в профиле |
| «Ключ профиля не задан» / «задан для другого адреса» | Ввести ключ на странице профиля; после смены адреса ключ вводится заново |
| Прогон на паузе «Подтвердите адреса сервера…» | Имя сервера стало указывать на другой адрес – проверьте и подтвердите новый |

Доступ к **интерфейсу** приложения из ВМ (обратное направление: браузер в ВМ – приложение на компьютере) – отдельное
решение, ADR-0103, раздел README «Доступ из локальной сети».
