# Задание агенту перевода интерфейса

Репозиторий приложения («Local Triage», FastAPI + Jinja2 + PostgreSQL). Интерфейс становится двуязычным:
английский по умолчанию, русский вторым языком (решение владельца 23.11.2026). Ключ перевода – русский текст в коде
(msgid, как в gettext). Прочитай целиком: `docs/i18n-plan.md`, `docs/i18n-glossary.md`, `app/i18n.py`,
`scripts/i18n_check.py`. Тебе даны **только свои файлы** – другие не трогай: параллельно работают другие агенты.

## Что сделать в своих файлах

1. **Обернуть каждую строку, которую видит человек** (текст страниц, подписи, кнопки, `title`, `aria-label`,
   `placeholder`, `data-busy`, `data-confirm`, сообщения об ошибках и успехе, тексты подсказок, тексты дефектов):
   - шаблон: `Текст` → `{{ _("Текст") }}`; в атрибуте `title="Текст"` → `title="{{ _("Текст") }}"`;
     подстановка – `{{ _("Найдено {n} находок", n=count) }}`; форма числа – уже есть `plural(n, "находка",
     "находки", "находок")` и фильтр `|plural(...)` – оставить, они переводятся сами; `{% block title %}` – тоже
     через `_()`;
   - Python: `"Текст"` → `i18n._("Текст")` (`from app import i18n`); f-строка `f"Найдено {n} находок"` →
     `i18n._("Найдено {n} находок", n=n)`; имена подстановок – латиницей, понятные; одна фраза – один msgid (не
     склеивать перевод из кусков: порядок слов в английском другой);
   - константы модуля, вычисляемые при импорте (`TEXT = "…"`, словари сообщений, `register_messages({...})`):
     перевод при импорте нельзя – язык меняется на ходу. Варианты: `N_("…")` у константы и `_(CONST)` там, где
     строка выводится; словарь подписей `{"key": "…"}` → `Labels({...})` из `app.i18n` (перевод при чтении);
     `register_messages({...})` переводится при выводе (`render` в `routes/common.py`): значения оставить
     строками, но перевести в каталоге (проверка полноты собирает значения `register_messages` сама);
   - JavaScript: `"Текст"` → `ltT("Текст")`, с подстановкой `ltT("Осталось {n} с", {n: s})`; формы числа –
     `ltPlural(n, "находка", "находки", "находок")`; `toLocaleString('ru-RU')` → `toLocaleString(ltLocale())`.
     Каждую строку JS добавить в часть каталога **`app/locales/en/js.json`** – она отдаётся в страницу целиком
     (если в группе есть JS – только твоя группа пишет в js.json).
2. **Перевести** все новые msgid своих файлов в свою часть каталога `app/locales/en/<группа>.json` (имя дано в
   задании): объект JSON `{"русский msgid": "English"}`, UTF-8, отступ 1, ключи по алфавиту не обязательно.
   Формы числа: ключ `"находка|находки|находок"`, значение `"finding|findings"`. Подстановки `{name}` – те же.
   Перевод – по словарю терминов, профессиональный английский интерфейса (как у GitHub, GitLab, Semgrep), без
   кириллицы. Если msgid уже переведён в другой части каталога – не дублируй с другим переводом (загрузка каталога
   упадёт); одинаковый перевод можно.
3. **Тексты дефектов** (`hub_defects.py`, `defect*.py`): по решению владельца язык текста дефекта – язык
   интерфейса, поэтому они тоже через `_()`. Не переводить значения-перечисления Hub (статусы Hub, ключи полей,
   типы), только человеческий текст.

## Правила по ревью плана Codex (обязательные)

- **Импорт в Python – только `from app import i18n`, вызов `i18n._("…")`** (и `i18n.N_`, `i18n.Labels`,
  `i18n.plural`). Голое `_` нельзя: в модулях есть распаковки `text, _ = …`, и `_()` выше по функции сломает
  обработчик (UnboundLocalError) только в ветке ошибки.
- **Строки, которые потом разбираются или сравниваются, распознаются на обоих языках.** Если приложение ищет в
  тексте заголовок раздела («Где исправлять:», «Обоснование:», «Рекомендация:»), префикс («Ложное срабатывание»,
  «Результат неизвестен») или сравнивает видимый текст (`worker_text != "Исполнитель на связи."`), то:
  генератор пишет на языке интерфейса, а разбор/проверка принимает **и русский, и английский** вариант независимо
  от текущего языка (константы-пары рядом, одна таблица для генератора и проверки). Сравнение видимых текстов
  заменить сравнением кода состояния.
- **Хранимые в базе тексты, по которым идёт классификация** (ошибки прогонов, причины): в базу пишется прежний
  русский канонический текст, перевод – только при показе (функция показа по известным префиксам).
- **Отпечатки отправленного текста** (отметки «Внесено в Hub», сравнение `text_hash` заново собранного текста с
  сохранённым): совпадение засчитывается, если совпал текст, собранный на любом из двух языков (`with
  i18n.use("ru")` и `with i18n.use("en")`). Исторические генераторы при русском дают прежние байты.
- **Подписи, вычисляемые при импорте** (`FILTER_GROUPS`, кортежи с `*LABELS.items()` на уровне модуля): хранить
  ключ или msgid, подпись получать при построении страницы.
- **JSON для JavaScript и SSE:** машинные ключи и коды состояния не переводятся; видимые поля (`state_label`,
  `phase_label`, `detail`, `error`, `text`) – переводятся на сервере.
- **HTML-страницы, собранные в Python** (не Jinja, например в `routes/components.py`): `lang` и текст – тоже
  через перевод.
- **Значения перечислений модели** (`cwe_fit`, `verdict_changes == "да"`, вердикты) – протокол, не переводятся; их
  показ – через подписи `Labels`.
- **CSS `content: "…"` с текстом** – убрать текст из CSS: `content: attr(data-label)` и атрибут в шаблоне через
  `_()`.

## Чего не делать (важно)

- Не оборачивать строки, **по которым идёт сравнение, поиск или разбор**: `if text == "…"`, `"…" in value`,
  регулярные выражения, ключи словарей, значения, которые пишутся в базу и потом сравниваются, имена листов и
  колонок Excel, значения, которые уходят в AppSec.Hub как перечисления, значения из `DEFAULT_STATUS_MAP`.
  Сомневаешься – не оборачивай и напиши об этом в отчёте.
- Не трогать `app/prompts.py` (промпт модели), `app/hub_import.py` (формат выгрузки), докстринги и комментарии,
  вызовы журнала (`log.info(…)`, `log_failure`), тесты.
- Не менять поведение и вёрстку: только обёртка строк и перевод. HTML внутри строки: `_()` возвращает обычную
  строку, Jinja её экранирует; если в тексте есть разметка (`<code>`, `<b>`, ссылка) – разбей так, чтобы разметка
  осталась в шаблоне, а переводились куски текста, или используй `{{ _("… {link} …", link=…)|safe }}` **только**
  если подставляемые значения не из данных пользователя. Данные пользователя никогда не попадают под `|safe`.
- `|tojson` у `Labels` отдаёт русские msgid – если словарь подписей уходит в JS через `tojson`, передавай
  `dict(labels.items())` (переведённые значения).
- Не запускать pytest (одна тестовая база на всех агентов) и не делать git commit/add.
- Не выдумывать: если смысл русской строки неясен из кода – переводи по контексту и отметь в отчёте.

## Проверка перед сдачей (обязательно)

```
cd <корень репозитория>
set PYTHONUTF8=1
.venv\Scripts\python scripts\i18n_check.py --raw <твои файлы>      # что осталось без перевода
.venv\Scripts\python scripts\i18n_check.py                           # полнота каталога (смотри только свои)
.venv\Scripts\ruff check <твои .py>
.venv\Scripts\python -c "import app.main"                            # импорт
.venv\Scripts\python scripts\i18n_template_check.py <твои .html>     # шаблоны собираются
```

В `--raw` для твоих файлов должны остаться только строки из списка «Чего не делать» – их перечисли в отчёте
с причиной (файл:строка – почему не обёрнуто).

## Отчёт (последнее сообщение, коротко)

Файлы и число обёрнутых строк; часть каталога и число переводов; что сознательно оставлено русским и почему;
сомнения по смыслу; итоги четырёх проверок.
