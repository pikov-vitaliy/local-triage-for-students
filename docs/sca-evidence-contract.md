# Контракт доказательств SCA и задание внешнему агенту

Действующий контракт `local-triage/sca-answers/2` реализован в 0.4.0 по
ADR-0065. Выпуск 0.4.1 использует схему базы 14 и валидатор
`sca-contract/2.0.2`. Ответы из выданных комплектов 2.0.1 принимаются с новыми проверками;
идентификатор задания, входные строки и прежний отпечаток манифеста сохраняются.
ADR-0064 остаётся предложением в части
архивов снимков первоисточников и расширенного протокола. Эти будущие функции не входят в текущий комплект.

За безопасность отвечает владелец продукта. SBOM не является секретным и отложен на следующий этап.
Hub здесь только источник полученного Excel, AST не исследуются и в задание не передаются.
Основа исследования – экосистема, координаты и текущая версия компонента.

## Действующий комплект

| Файл | Назначение |
|---|---|
| `manifest.json` | Идентификатор, хеш состава, неизменяемые строки, лимиты и версия валидатора |
| `components.json` | Исходные имена и версии, вид идентичности, кандидат исправления из Excel |
| `task.md` | Задание, источники, правила вывода и самопроверки |
| `answer.template.json` | Заготовка, которую нужно заполнить; пустая заготовка отклоняется |
| `answer.schema.json` | Машинная схема из того же описания полей, что валидатор |
| `validate.py` | Самодостаточный валидатор на Python 3.11, только стандартная библиотека |

`python validate.py --manifest manifest.json --answer answer.json --report report.json`:
код 0 – принято, 2 – нарушение контракта, 3 – техническая ошибка. Приложение проверяет файл заново
своим валидатором. Присланный исполняемый файл не запускается, отчёт агента не заменяет проверку.
Файл или текст JSON загружаются в «Компонентах»; прежняя форма SCA предназначена для контракта 1.

## Поля и вычисляемые состояния

`input_ref`, `ecosystem`, `component`, `current_version` неизменяемы, включая пустую экосистему.
Подтверждённая координата хранится отдельно в `identity_resolution`. Для краткого Maven/npm имени
нужны основание namespace, опубликованная текущая версия и успешная проверка identity.
`latest_stable_release`, `update_status`, `support_status` не подменяют друг друга.

`public_findings` содержат ID и aliases, описание, applies yes/no/unknown, ranges, условия,
fixed_versions, CVSS и source_refs. Диапазоны: introduced включён (0 – начало истории),
fixed исключён, last_affected включён; несколько диапазонов объединяются. Противоречие yes/no
известному диапазону отклоняется. При неизвестном порядке нужны applies=unknown и gap
APPLICABILITY_UNCLEAR. Старые сохранённые ответы задним числом не перепроверяются: показывается пометка
о прежних правилах, факты и решения остаются доступными.

`package_status` вычисляется: неразрешённая идентичность – identity_unresolved; применимая находка –
vulnerable; неизвестная применимость или неполный поиск – incomplete; полный успешный поиск без
применимых находок – no_known_vulnerabilities. Отсутствие известных записей относится к проверенному
охвату и дате, а не гарантирует отсутствие уязвимостей.

`research_coverage` уникален по паре (source, purpose), содержит точный запрос, статус, complete,
дату и ссылки на evidence. Один реестр может подтверждать identity и releases.
`evidence` имеет уникальные evidence_ref и URL; один ref можно использовать в нескольких утверждениях.
Ссылки публичные HTTP(S), без userinfo, локальных адресов и неоднозначных форм IPv4/WHATWG.
Каждая запись содержит дату, тип, основание, цитату и уровень источника. Ответы HTTP 403 не доказывают
прочтение страницы; доступность и происхождение объясняются в охвате и gaps.

`package_advice` – совет, решение оператора хранится отдельно. При отсутствии исправления компонент
остаётся vulnerable. Для update нужны опубликованный целевой релиз и источники. Up_to_date требует
последнего релиза и непустых source_refs. Приложение поддерживает npm/cargo SemVer,
числовые релизы NuGet/Composer, PEP 440 и RubyGems; Maven – числовые сегменты и стандартные квалификаторы.
Неизвестные формы возвращают неопределённый порядок. Совет update и update_available сохраняются,
но список и карточка заметно показывают «порядок версий не проверен приложением».

Источники правил сравнения: [PEP 440](https://packaging.python.org/en/latest/specifications/version-specifiers/),
[NuGet](https://learn.microsoft.com/en-us/nuget/concepts/package-versioning),
[SemVer 2](https://semver.org/spec/v2.0.0.html),
[RubyGems](https://guides.rubygems.org/patterns/#semantic-versioning).

## Действующие коды ошибок

Все ошибки отклоняют новый импорт целиком, без частичной записи. Структурно корректный неполный
результат принимается с конкретными gaps. Полнота множества строк обязательна.

| Код | Проверка |
|---|---|
| SCA-M001 | JSON, кодировка, повтор ключа или неканоническое число |
| SCA-M002 | Предел размера, длины строки или количества элементов |
| SCA-M003 | Лишнее поле |
| SCA-M004 | Отсутствующее обязательное поле |
| SCA-M005 | Тип, перечисление, шаблон, уникальность или числовая граница |
| SCA-M006 | Предел глубины JSON |
| SCA-M007 | Отчёт содержит только первые ошибки с явной пометкой |
| SCA-T001 | Заявленное состояние не совпадает с вычисленным |
| SCA-T002 | Несовместимый контракт, валидатор или идентификатор задания |
| SCA-C001 | Неизвестная строка задания |
| SCA-C002 | Изменённое входное поле или чужая координата |
| SCA-C003 | Пропуск, повтор строки или неверное число строк |
| SCA-C004 | Неверный отпечаток манифеста |
| SCA-E001 | Источники, evidence_ref, URL, ссылки публикации, доказательства идентичности |
| SCA-D001 | Дата в будущем |
| SCA-L001 | Неисследованная строка или логическое противоречие |
| SCA-A001 | Внутренний номер AST либо противоречие применимости диапазону |

Численные пределы объявлены в `LIMITS` и схеме из `app/sca_contract.py`: ответ 16 МиБ, строка
512 КиБ, 5000 компонентов, 500 находок и 128 доказательств на компонент, глубина 12.
Превышение отклоняется, текст и ссылки не обрезаются молча. В отчёте максимум 200 ошибок плюс M007.

## Ревизии и повторная проверка

Состав сравнивается по строкам, отсортированным по input_ref; CVSS и порог не меняют состав.
Изменение фактов создаёт новую ревизию, помечает прежнее решение для пересмотра. Изменение только
checked_at/as_of обновляет последнее наблюдение без новой ревизии фактов и без отмены решения.
Схема 14 добавляет content_sig, observation_json, observed_at и validation_rules; прежние answer_sig и привязки
не переписываются. Решения по компонентам вне текущей выгрузки остаются видны независимо от возраста задания.

## Приёмка и границы

Тесты `test_audit_041_contract.py`, `test_audit_041_visibility.py`, `test_audit_041_group1.py`,
`test_sca_research_contract.py`, `test_sca_research_routes.py` проверяют позитивные и отрицательные пути.
Браузерный цикл – `tests/e2e/test_component_research.py`. Структурная согласованность не доказывает
истинность сайта, полный охват всех открытых источников, минимальность версии среди всех веток или
эксплуатируемость в конкретном приложении. Оператор принимает решения по доступным фактам.

## Задание внешнему агенту

Точный действующий текст хранится в `sca_research.task_text` и входит в скачанный `task.md`, а не
переписывается вручную в документации. Исследователь сохраняет исходные поля, устанавливает координаты,
исследует релизы, поддержку и публичные уязвимости, фиксирует источники и пробелы, выполняет validate.py
до выдачи результата. Неизвестные AST не являются задачей, условием успеха или причиной неполноты.
