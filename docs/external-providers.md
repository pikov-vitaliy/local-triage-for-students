# Внешние провайдеры моделей: API чат-завершений и Anthropic Messages API по ключу

С 0.9.13 профиль провайдера может указывать на сервер в интернете с API чат-завершений, с 0.9.14 – и с Anthropic
Messages API (ADR-0106) – платную подписку или публичный API по ключу
(ADR-0104). Код находок туда
по умолчанию не уходит: исследование компонентов внешней моделью получает обезличенный состав задания
(ADR-0105), а разбор кода – только проект с отметкой «код не
секретный» после предпросмотра. Промежуточная сборка 0.9.13.dev1 умеет создать профиль, проверить сервер, получить
пробный ответ и проверить поиск; 0.9.13.dev2 – исследование компонентов провайдером и отметка «код не секретный».

## Включить внешних провайдеров на установке

Внешние провайдеры выключены, пока приложение не запущено с переменной `LLM_EXTERNAL=1`: из интерфейса её не
включить, поэтому в закрытом контуре внешний запрос нельзя отправить кнопкой.

1. В `.env` рядом с `docker-compose.yml` – строка `LLM_EXTERNAL=1`.
2. Перезапуск через `.\start.ps1`: он передаёт контейнеру адреса этого компьютера (`TRIAGE_HOST_ADDRESSES`) и
   запускает сборщик метрик хоста, который раз в минуту обновляет их в `data/telemetry/host.json`. Без свежих адресов
   компьютера внешний запрос из контейнера не уходит: иначе нельзя исключить обращение к самому компьютеру.
   После перезагрузки компьютера сборщик сам не запускается – список и профиль внешнего провайдера предупреждают об
   этом с командой запуска: `.\scripts\host-metrics.ps1 -Action Start` из папки приложения.

Выключить – убрать строку и перезапустить: профили остаются, каждый внешний запрос отклоняется до сети.

## Профиль

«Настройки → Провайдеры моделей → Добавить профиль», протокол «API чат-завершений» или «Anthropic Messages API»,
сервер «Интернет».

| Поле | Что вводить |
|---|---|
| Адрес | база API из документации провайдера, только `https`. Чат-завершения: к ней добавляются `/models` и `/chat/completions`. Messages API: `/models` и `/messages` – адрес вводится вместе с `/v1`, если провайдер следует пути Anthropic `/v1/messages`; правильность адреса подтверждает «Пробный ответ» |
| Ключ API | один раз; хранится файлом в папке данных, привязан к адресу; на странице – «задан, …последние 4 знака». Чат-завершения – заголовок `Authorization: Bearer`, Messages API – `x-api-key` и служебный `anthropic-version: 2023-06-01` |
| Модель по умолчанию | из списка «Проверить» или вручную – имя как у провайдера; имена сравниваются точно, с учётом регистра. Сервер не отдаёт список моделей (`/models` – 404/405/501) – в списке имя из профиля с пометкой, есть ли модель у провайдера, покажет «Пробный ответ» |
| Формат ответа | чат-завершения: `json_object` – ответ объектом JSON, проверка приложением; `json_schema` – если провайдер его поддерживает; «без формата». Messages API: `tool` – ответ вызовом инструмента `answer`; `tool_strict` – то же со строгой схемой, если сервер её поддерживает; «без формата» – текст. Проверка приложением – всегда |
| Рассуждение – поле `thinking`, уровень – поле `reasoning_effort` | только у чат-завершений: значения из документации провайдера; «не передавать» – как решит сервер. Протоколу Messages рассуждение не передаётся |
| Окно контекста модели, предел ответа | промпт вместе с ответом и схемой ответа должен поместиться в окно – срез кода подгоняется под окно профиля; пусто – окно не проверяется, предел 8192. У внешнего провайдера лимиты видеокарты не действуют: окно и предел ответа – по документации модели провайдера |
| Шагов поиска на компонент | технический ограничитель цикла исследования (1–40, по умолчанию 12) – защита от зацикливания, не от расхода |
| Срок одного обращения | по умолчанию 600 с; у «Пробного ответа» – тот же срок профиля |
| Поисковый API провайдера | пути поиска и получения страницы от корня того же адреса (тот же сервер и ключ) |

Кнопки: «Проверить» – список моделей (генерацию это не доказывает); «Пробный ответ» – один короткий ответ выбранным
форматом и рассуждением (расходует токены); «Проверить поиск» – один запрос поиска (расходует запрос). Лимиты расхода
приложение не ведёт – они в личном кабинете провайдера.

Внешний профиль не бывает профилем по умолчанию для разбора кода – умолчание действует на все проекты, в том числе с
секретным кодом. Профиль выбирают в нужном проекте («Параметры проекта», поле «Профиль модели») или при запуске
разбора – после отметки проекта «код не секретный».

**DeepSeek по Messages API.** У DeepSeek есть Anthropic-совместимый вход: базовый адрес для Anthropic SDK –
`https://api.deepseek.com/anthropic`, заголовок `anthropic-version` он игнорирует, `x-api-key` поддерживает
([Anthropic API, DeepSeek](https://api-docs.deepseek.com/guides/anthropic_api), открыто 25.10.2026). Какой путь к
нему добавлять и какие имена моделей принимаются, на этой странице прямо не сказано – совместимость с приложением
владелец проверяет «Пробным ответом» до прогона.

## Отметка «код не секретный»

Код находок уходит внешнему провайдеру только у проекта с отметкой – по решению владельца кода, не приложения.

1. На странице проекта – «Параметры проекта → Код внешнему провайдеру → Предпросмотр и отметка…».
2. Страница предпросмотра показывает ровно то, что уйдёт провайдеру по каждой находке SAST: инструкции модели и
   сообщение с описанием находки и срезом кода вокруг строки – на примере первой находки очереди, с тем же
   маскированием секретов и персональных данных, что в прогоне; каким внешним профилям код может уйти; что
   раскрывается косвенно (пути файлов и код – устройство этой части системы). Название проекта, решения оператора и
   остальной код репозитория не отправляются.
3. Обоснование (10–1000 знаков: открытый код, демонстрационный проект, разрешение владельца системы…) и флажок
   подтверждения. Обоснование и время отметки видны в параметрах проекта. Отметка ставится только с этой страницы и
   только когда показать есть что: без находки SAST в проекте её не поставить. Маскирование – эвристика: то, что не
   похоже на секрет или персональные данные по образцам, уйдёт как есть.
4. После отметки внешний профиль выбирается профилем модели проекта; код уходит прогоном, вопросом к модели или
   пересмотром находки на таком профиле – каждое обращение оплачивается у провайдера.

Снять отметку можно в любой момент: начатая отправка заканчивается, следующая находка не уходит, идущий прогон встаёт
на паузу с подсказкой, новый прогон на внешнем профиле не ставится в очередь. Отметка не ставится, пока на установке
нет `LLM_EXTERNAL=1`. Демонстрационный проект отметку сам не получает.

## Разбор кода внешней моделью

Прогон и «Пересмотреть вердикт» идут профилем проекта, «Спросить модель» – профилем, которым получен разбор (иначе
профилем проекта); отличия внешнего провайдера:

- каждое обращение платное, а готовых ответов «по ключу запроса» нет (у провайдера нет отпечатка весов модели):
  «заново» – всегда новый запрос по каждой находке;
- если запрос ушёл, а ответа нет (обрыв связи после передачи, 502, 504), находка получает ошибку «результат
  неизвестен»: запрос мог быть принят и оплачен. Такая находка повторно не отправляется ни «Продолжить», ни после
  перезапуска приложения; «Повторить ошибочные» – новый платный запрос, только по вашему решению, и находку, которую
  уже разобрал более поздний прогон, он не берёт. С вопросом к модели – так же;
- с отметкой профиля «Повторять после обрыва без ответа» обрыв без ответа – один автоматический повтор того же
  запроса; второй обрыв – «результат неизвестен». Серия обрывов (3 находки подряд или больше 10 % прогона, но не
  меньше 3; у исследования – 3 строки подряд) – прогон на паузе, получение остановлено с причиной, а не новые запросы
  (ADR-0107). Карточка находки пишет «повтор после обрыва связи»;
- имя сервера не разрешилось службой имён (DNS) – запрос не отправлен и не оплачен: имя опрашивается до трёх раз с
  паузами 1 и 2 с; в исследовании провайдером ход модели повторяется ещё раз через 10 с, запрос инструмента – через
  5 с, «Остановить» прерывает паузу (строка в очередь, если в ней не было запроса с неизвестным исходом); второй сбой
  хода – строка «не получена» с причиной, без «результата неизвестен», второй сбой инструмента – модели уходит ошибка
  инструмента, и строка продолжается по собранному; сбой после настоящего обрыва исход первого запроса известным не
  делает (ADR-0113). Служба имён компьютера, идущая
  через туннель VPN, может отвечать отказом на доли секунды;
- ответ получен, но непригоден (оборван по длине, отказ модели, ответ не по протоколу) – обычная ошибка находки с
  расходом ответа, повтор – «Повторить ошибочные» без отметки неизвестных;
- 402 от провайдера – прогон на паузе с причиной «пополните баланс»; находка остаётся в очереди. Если 402 пришёл на
  автоматический повтор после обрыва, находка – «результат неизвестен» первого запроса (её «Продолжить» не
  отправит), прогон – на паузе с той же причиной;
- скорость генерации провайдер не сообщает – страница прогона показывает «Где работает модель» и скорость ответа по
  времени модели (с ожиданием сервера); метрик видеокарты и памяти этого компьютера у внешнего прогона нет;
- полоса «идёт получение» наверху любой страницы ведёт к ходу исследования компонентов, как «ход разбора» – к прогону.

## Запрос OSV перед исследованием

С 0.9.18 по согласиям, выданным при включённом `OSV_URL` (адрес записан в текст инструкций согласия; прежние
согласия работают без OSV), перед каждой строкой исследования приложение само запрашивает OSV (`POST https://api.osv.dev/v1/query`:
экосистема, имя и версия компонента – ровно то, что и провайдеру) и кладёт ответ в поле `osv` первого сообщения
модели (ADR-0112). Адрес – `OSV_URL` в `.env` (пусто – api.osv.dev, `off` –
не запрашивать по новым согласиям; согласие с записанным адресом продолжает его использовать, «Продолжить» и
«Доисследовать оставшиеся» адрес не меняют); правила адреса те же, что у внешних провайдеров; обмен – в журнале обмена (назначение
`research:osv`); сбой запроса строку не останавливает. Предпросмотр согласия показывает адрес и состав запроса.

## Защиты

- Только `https`; сертификат проверяется по имени хоста из системного хранилища контейнера; перенаправления не
  выполняются; прокси не используются.
- Имя разрешается на каждый запрос, соединение – только с глобальными адресами: частные сети, loopback, link-local,
  CGNAT, переходные диапазоны IPv6 со встроенным IPv4 и адреса самого компьютера (IPv6 – весь его /64) – отказ.
- Ключ уходит только адресу, к которому привязан; смена адреса удаляет ключ.
- Повторы: после 429 и временных ошибок сервера (500, 503; у Messages API ещё 529) – один, с ожиданием
  `Retry-After`; на одно обращение – не больше трёх отправок. Сбой после начала передачи запроса, 502 и 504 –
  «результат неизвестен»: без отметки профиля автоматического повтора нет, с отметкой – один (ADR-0107).
  402 – остановка с причиной «пополните баланс».
- Право на генерацию: у внешнего провайдера своё, локальная видеокарта его не ждёт и не занимает.
- Код проекта – только при отметке «код не секретный»: проверяется при выборе профиля и перед каждой отправкой под
  общей блокировкой проекта; снятие отметки берёт исключительную, поэтому запрос, начатый до снятия, уходит целиком,
  а следующий – нет.
- Исследование компонентов: запуск только со страницы предпросмотра (серверная метка страницы), повтор формы не
  создаёт второго получения; перед каждой отправкой сверяются согласие, профиль и фактический состав проекта.

## Журнал обмена

Журнал ([model-traffic-log.md](model-traffic-log.md)) хранит обмен с внешним провайдером байт в байт, как и с
Ollama; вырезается только заголовок авторизации. Журнал – локальный, его конфиденциальность обеспечивает владелец.

## Откат промежуточной сборки

Выпуск 0.9.14 схему базы не меняет (23). Откат на 0.9.13.dev4 – остановленный контейнер и образ
`local-triage:0.9.13.dev4`; профили Messages API прежняя сборка не исполняет (протокол ей неизвестен – запрос не
отправляется), отметка «Повторять после обрыва» ею игнорируется.

Сборка 0.9.13.dev1 схему базы не меняет, но добавляет профили нового вида. Откат – остановленный контейнер, копия
папки данных, снятая перед развёртыванием, и прежний образ по тегу.

Сборка 0.9.13.dev2 переводит базу на схему 23 (копия базы перед шагом 22 → 23 снимается самим приложением –
`triage.before-schema-22-to-23-….db`). Откат на 0.9.13.dev1 – остановленный контейнер, эта копия базы на место
`triage.db` (файлы `-wal` и `-shm` удалить) и образ `local-triage:0.9.13.dev1`; откат на 0.9.12 – копия папки
данных, снятая перед развёртыванием dev1, и образ `local-triage:0.9.12`. Согласия на исследование, получения и
отметки проектов после отката не сохраняются – они есть только в схеме 23.
